Documenting the failure mode turned out more valuable than documenting the happy path. Idempotency mattered far more than throughput on this path, which inverted our original priorities. ## The lesson

Timeouts landed at 10% change once I measured it end to end. Three deploys in, the pattern was obvious: the migration degraded before anything else did. Because the consumer fell behind quietly, the first symptom was a customer report. Because a timeout longer than the caller's is not a timeout but a leak, we shortened it deliberately. Under normal load the timeout budget behaved; under peak it did not, and only peak mattered. Small boring changes with a measurement attached beat clever changes without one, every time. Retries around the cache layer made the symptom disappear and the underlying problem considerably worse. We added one metric, waited a week, and the cause became embarrassingly clear.
