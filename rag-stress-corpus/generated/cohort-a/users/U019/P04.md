## The lesson

We added one metric, waited a week, and the cause became embarrassingly clear. The config that caused it had been in place for months without incident. The rollback plan was the part nobody had rehearsed, which is reliably the part that matters.

Because a timeout longer than the caller's is not a timeout but a leak, we shortened it deliberately. That gave queues of 11% change, which I wrote down at the time. The failure was intermittent, so every fix looked correct for a while before the retry path broke again. Because the consumer fell behind quietly, the first symptom was a customer report. Under normal load the cache layer behaved; under peak it did not, and only peak mattered.
