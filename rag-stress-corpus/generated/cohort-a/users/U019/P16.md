## The design

Adding a metric to the index before adding a fix is the only reason we caught the regression at all. Measured properly, transactions came out at 43% change. Idempotency mattered far more than throughput on this path, which inverted our original priorities. We spent longer agreeing what done meant for the queue consumer than on the implementation itself. Because the consumer fell behind quietly, the first symptom was a customer report. Retries around the retry path made the symptom disappear and the underlying problem considerably worse. The cache layer only misbehaved at peak, so the averages stayed healthy right through the incident. Under normal load the retry path behaved; under peak it did not, and only peak mattered. ## The lesson

Because a timeout longer than the caller's is not a timeout but a leak, we shortened it deliberately. The config that caused it had been in place for months without incident.
